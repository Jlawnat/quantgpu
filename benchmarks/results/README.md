# Benchmark Results

This directory stores preserved benchmark artifacts generated by QuantGPU.

The saved CSV files are the source of truth for reported performance results.
Historical benchmark artifacts are retained rather than silently overwritten.

## CPU/GPU baseline

`cpu_gpu_comparison_v2.csv` contains the frozen CPU-versus-GPU benchmark across:

- NumPy CPU
- PyTorch CPU
- PyTorch CUDA FP64

The path-count ladder includes:

```text
10,000
100,000
1,000,000
5,000,000
10,000,000
```

For the 10-million-path workload, the preserved result reports approximately:

```text
NumPy CPU          367.65 ms
PyTorch CPU        639.39 ms
PyTorch CUDA FP64   10.67 ms
```

This corresponds to approximately:

```text
34.45× CUDA speedup vs NumPy CPU
59.91× CUDA speedup vs PyTorch CPU
```

Headline CPU-versus-GPU comparisons use end-to-end median latency.

## GPU optimization benchmark

`cuda_optimization_comparison_v2.csv` contains the final GPU optimization study.

It compares:

```text
torch_cuda_fp64
torch_cuda_fp32
torch_cuda_fused_fp32
torch_cuda_compiled_fp32
triton_cuda_fp32
```

For the 10-million-path workload, the selected Triton backend reports
approximately:

```text
Device median latency      0.674 ms
End-to-end median latency  0.683 ms
Throughput                 14.83 billion paths/s
```

Within the same optimization benchmark, Triton is approximately:

```text
4.48× faster than eager PyTorch FP32
2.09× faster than compiled PyTorch FP32
16.63× faster than the same-run FP64 CUDA implementation
```

See:

```text
docs/gpu_optimization_summary.md
```

for the optimization progression and interpretation.

## Benchmark policy

Raw benchmark artifacts are append-only in spirit.

A benchmark schema, methodology, or materially different experimental result
should write to a new versioned filename rather than overwrite historical
evidence.

Scratch outputs belong under ignored locations such as:

```text
benchmarks/results/raw/
profiles/
```

## Recorded metadata

Modern benchmark rows record the context required to interpret and reproduce a
result, including where applicable:

- schema version
- execution timestamp
- backend
- device
- dtype
- workload parameters
- path count
- warm-up count
- repetition count
- latency statistics
- throughput
- estimated option value
- analytical reference value
- numerical error
- Monte Carlo standard error
- random seed
- Git commit SHA
- Git working-tree state
- QuantGPU version
- Python version
- NumPy version
- PyTorch version
- CUDA version
- Triton version
- CPU model
- GPU model
- validation status

## Schema versioning

Historical benchmark CSVs are preserved unchanged.

Schema `1.1` adds reproducibility provenance fields including:

- `git_commit`
- `git_tree_state`
- `quantgpu_version`
- `numpy_version`
- `torch_version`
- `cuda_version`
- `triton_version`
- `spot`
- `strike`
- `maturity`
- `rate`
- `volatility`
- `dtype`
- `cpu_model`
- `gpu_name` for CUDA results
- `validation_status`

New benchmark schema versions write to new versioned result files rather than
rewriting existing benchmark artifacts.

## Reporting principle

Headline performance numbers should be derived from committed benchmark data,
not copied from transient terminal output.

A benchmark number without workload, hardware, precision, validation, and
provenance context should not be treated as a reproducible result.
